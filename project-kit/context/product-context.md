# Product context — 404HubSpot

404HubSpot is a Kenya-focused digital services and programming training website.
Visitors compare web development, software, mobile apps, M-Pesa integrations, design,
and programming classes, then inquire through WhatsApp or the existing contact page.

## First feature

Revamp the entire landing page and its shared navigation/footer while retaining all
nine existing routes, service descriptions, team identities, and contact destinations.
The user authorized choosing and implementing the visual direction from Griot references.
The baseline setup is supporting planning for this one feature, not a separate app migration.
No backend, framework migration, deployment, or invented customer metrics.

## Journeys

- Business visitor → service card → existing service detail → inquiry.
- Learner → training section → programming classes → class inquiry.
- Returning visitor → navigation or footer → contact/process/services, at any viewport.

Success: complete landing-page redesign; accessible menus; every existing route still
renders; no horizontal overflow at 360, 768, 1024, 1440, and 1920 pixels.

## Whole-system planning scope (user follow-up)

33 detailed feature specs cover complete company portfolio revamp and staged full-stack growth.
Required future logical capabilities include backend/data, staff operations, AI and MCP.
Use a modular monolith first. Native mobile and independent microservices remain evidence-gated;
no empty application folders or speculative infrastructure. Eight layer kits document ownership.
Only spec 01 is implemented here; roadmap specs remain planned and get separate branches.
